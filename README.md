# 冷链智运 — 配送决策研究演示系统

已按用户提供的实施方案改造为：自然语言任务路由 → 多车经典 ALNS → 独立硬约束校验 → 路线和成本展示 → 执行状态推进 → 动态事件重规划。

这是一套可运行的研究演示系统，不是已部署的生产系统，也不等于已完成全部参赛交付物。旧文档中的“效率提升30%”“收敛提升50%”“覆盖四大赛题”等说法缺少本工程证据，不能沿用。

## 启动

在本目录运行：

```powershell
python -m pip install -r requirements.txt
$env:PORT='8088'
python app.py
```

访问 http://127.0.0.1:8088 。也可双击 `start_demo.cmd`。默认脚本使用8088，避免占用原项目8080服务。后端模块使用标准库、Flask、Pandas、Openpyxl；前端没有 CDN 依赖，可以离线加载。建议 Python 3.11+；本次在 Python 3.13.13 下验证。

## 演示流程

1. 默认载入明确标注的25客户合成数据，或下载Excel模板并上传真实数据。
2. 输入“请优化碳排放”，或选择成本/排放/距离目标运行工具。
3. 在“路径与约束”查看访问顺序、服务开始时刻、容量和独立校验。
4. 在“动态事件”推进一次配送：每车服务下一客户后停车，冻结已完成任务，统一事件时刻。
5. 新增 N01 订单，查看回仓补货后的剩余方案。新增货物必须通过仓库装载；所有携货车辆到齐后才允许重新配货。
6. 在“结果分析”比较同事件下插入基线与ALNS结果，导出审计记录。

坐标插单支持默认合成数据，以及通过坐标、欧氏距离、40 km/h 时间矩阵一致性核验的系统模板和Excel。旧四表模板缺少仓库坐标时，仅在全部矩阵与仓库(25,25)吻合后恢复。真实路网须在自定义事件JSON提供新节点到所有旧节点、以及所有旧节点到新节点的距离/时间，不假定对称。

## 恢复初始状态

右上角“恢复初始状态”恢复本次载入的数据及最近一次基于该数据的初始可行方案，撤销配送推进、新增订单、车辆不可用和时间窗变更。未求解时恢复到待求解状态。50/100客户数据保持原规模。恢复前完整状态自动保存到 `outputs/reset_archives/`，重复恢复不会覆盖恢复点。

“载入演示数据”是另一个按钮：明确切换到默认25客户，并建立新的恢复点。重新上传文件也会替换恢复点。当前恢复点随会话保存在服务内存中，普通页面刷新可保留；重启服务后仍需重新导入数据。

## 数据格式

Excel四个sheet：

- `orders`：id（字符串）、demand（kg）、ready/due/service（min）；可选x/y坐标。
- `vehicles`：id（字符串）、capacity（kg）；可选available布尔值。
- `distance_km`：无表头的完整距离矩阵。
- `time_min`：无表头的完整行驶时间矩阵。

矩阵顺序必须是 DEPOT、orders各行。拒绝维度错误、重复id、负数/NaN/Inf、非对角零距离或零时间。当前上限150客户、30辆车，为100客户动态插单预留余量。JSON对应 `orders`、`vehicles`、`distance_matrix`、`time_matrix`，可另提供 `cost_parameters`。Excel目前采用默认成本系数，正式实验需通过JSON提供校准参数。

旧参考算例已随旧系统移至工作目录外的备份文件夹，不是当前系统运行依赖。当前可导入算例保留在 `data/demo_25.json` 及 `outputs/cases_20261108/`、`outputs/template_cases_20261108/`。这些是合成算例，不是Solomon数据或企业实际订单。

## 数学口径与边界

- 硬容量、硬服务开始时间窗、客户恰好服务一次、车辆可用性；缺单时返回 `no_feasible_solution_found`，不能误称已证明无解。
- 燃油 = 每段公里 ×（空载升/公里 + 满载增量升/公里 × 该段载重/容量）。返回段按剩余载重计算。
- 制冷耗电 = 功率 × 行驶/等待/服务持续时间；动态回仓及回仓等待也计入。
- 总成本 = 车辆启用 + 燃油 + 制冷。示例不采用软窗罚金和碳价格；排放仅统计，不重复计费。
- 默认系数仅是可配置示例，未声称具有企业实测依据。温控约束只建模持续制冷能耗，**未模拟温度轨迹、货损、制冷机效率变化或温区匹配**。
- 三种目标分别运行，不是多目标Pareto求解。固定随机种子在未触及时限时可复现；触及时限后迭代数受机器性能影响。
- 动态执行采用离散服务边界，没有真实GPS/道路中途位置。所有在途车辆回仓、携货车辆到齐后重配，装卸时长暂为0。此策略保守，不能声称最优现场插单策略。
- 仅支持发车前车辆不可用；在途故障因缺少救援和货物转运数据明确拒绝。未完成订单可修改时间窗，已完成历史不允许修改。
- 动态成本是从事件时刻起的剩余费用，不含已发生费用。与“原初计划总成本”不在同一口径，不能据此报告降本率。
- 当前无司机工时/班次、回仓截止、充电、异温区、货物分批取送模型。真实业务使用前须补齐对应约束。

## 工程与复用情况

- `coldchain/model.py`：标准输入、分段载重能耗、独立约束校验、KPI。
- `coldchain/solver.py`：多车经典ALNS、随机/空间关联破坏、增量插入、自适应算子权重、退火接受、随机种子、时间预算。
- `coldchain/replanning.py`：执行快照、已完成前缀、回仓补货、事件适配和公平基线比较。
- `coldchain/planner.py`：单主控任务路由、LLM function calling、离线规则模式、确定性说明。
- `server.py` / `app.py`：API、会话隔离、原子提交、历史及JSON审计。
- `web/`：四个工作台页面，离线资源、真实结果绘图、移动布局。
- `tests/`：后端回归、离线任务评测、25/50/100规模实验和浏览器测试。
- `outputs/evaluation/`：输入、真实结果、离线30任务标签及实测报告。
- `outputs/browser/`：桌面/手机截图及浏览器验收记录。

2026-11-09整理后，原 `logistics_agent.py`、论文算法目录、旧入口、旧页面及旧文档已完整移至工作目录外备份，具体位置见上级目录的《整理说明.md》。当前系统不依赖这些旧文件。原Q3是依赖Kaiwu的单车量子修复实现，不能原样作为多车硬容量求解器。本次沿用其随机/空间关联破坏思路，新增经典多车实现；**没有调用量子硬件，也没有复现原论文M1/M2/M3结果**。

## API

GET `/api/state`、`/api/template`、`/api/export`；POST `/api/data`、`/api/optimize`、`/api/agent`、`/api/advance`、`/api/replan`、`/api/reset`。

动态事件示例：

```json
{"type":"time_window","order_id":"C01","ready":0,"due":180}
```

```json
{"type":"vehicle_unavailable","vehicle_id":"V04"}
```

真实新增客户还需 `distance_to`、`distance_from`、`time_to`、`time_from` 数组，各为旧节点数（含仓库）。无需提供新点自身元素，程序补0。

## 部署限制与后续验收

本机演示默认仅监听127.0.0.1。Docker维持单worker；状态在内存中按浏览器会话隔离，写请求串行。审计文件原子写入outputs，含每版输入/执行状态/结果；重启后不会自动恢复会话。没有账户、权限管理、任务队列或生产级多用户持久化，不能直接公开承载真实客户数据。浏览器会话上限100；导入数据会重置当前会话计划，请先导出。

下一阶段仍需：真实数据单位与成本标定、真实LLM端到端评测、车辆救援转运、执行轨迹接入、原模型对照与多种子实验，以及PPT/演示视频/正式提交材料。赛事日期和提交规范未在本轮核验，不应将旧文案当作当前官方要求。
